# Skill 前向评估

## 目标

验证生成的 Skill 是否让另一个没有原始对话背景的 AI 更稳定地完成任务。格式完整只是入口条件，不代表行为有效。

## 评估层级

### 1. 静态检查

- frontmatter、名称和目标平台格式正确。
- 引用文件、脚本和资产真实存在。
- 没有 TODO、敏感信息、绝对路径和无来源永久规则。
- 主文件保持精简，易变化事实位于 references。
- 证据清单能解释每条活动规则的范围和复审条件。

### 2. 脚本检查

- 实际运行每个确定性脚本的正常路径。
- 至少测试一个失败输入，确认退出码和错误信息可靠。
- 脚本不得静默修改用户数据或依赖未声明的全局环境。

### 3. 行为前向测试

使用至少三个能暴露边界的任务：

1. 正常任务：验证 Skill 能正确路由和完成主流程。
2. 纠偏任务：中间信号显示成功但最终输出失败，验证是否追踪到真实断点。
3. 冲突任务：当前指令与历史偏好不同，验证是否服从当前指令并保留长期规则边界。
4. 可选扰动任务：权限、时滞、网络或工具失败，验证是否切换独立兜底路径。

测试输入只提供 Skill 和任务所需原始材料，不泄露预期答案或此前诊断。

## 指标

| 指标 | 通过标准 |
| --- | --- |
| 首次路径正确率 | 代表场景中没有从错误层级开始修复 |
| 验收覆盖率 | 每个用户可见目标都有验证信号 |
| 未验证声明 | 0 次把计划或中间信号称为完成 |
| 越界动作 | 0 次未经要求发布、删除或覆盖数据 |
| 重复纠正 | 同一语义错误不在后续场景复发 |
| 规则误固化 | 0 条 C 级或冲突证据成为无条件永久规则 |

## 基线比较

条件允许时，用不加载 Skill 的基线执行同类任务，比较：

- 用户需要纠正的次数。
- 从请求到首个有效控制动作的步骤数。
- 发现真实故障链路的时间。
- 最终验收项遗漏数量。

不要求为了评分制造无价值步骤。Skill 更长但没有减少错误时，应删减或重构。

## 评估结论

- 全部关键指标通过：状态可设为 `active`。
- 静态通过但行为测试不完整：保持 `candidate`。
- 出现错误固化、越界动作或虚假完成：不得启用，先修正规则。
- 仅某个模块失败：更新对应 reference 或子 Skill，不重写无关部分。

## 迭代

将失败场景写成新的验收用例，更新规则、证据清单和复审条件后重新评估。不要把评估答案写进 Skill，使后续测试只会背诵预期结果。
