# 可操作控制模型

## 目的

把控制论从概念类比转化为可执行决策。不要为了形式伪造数值模型；当变量不能量化时，使用明确的离散状态、条件和验证信号。

## 基本模型

将第 `k` 轮对话后的任务状态记为 `x_k`，控制动作为 `u_k`，外部扰动为 `d_k`，可观测输出为 `y_k`：

```text
x_(k+1) = F(x_k, u_k, d_k)
y_k     = H(x_k) + v_k
e_k     = r_k - y_k
```

- `r_k`：当前目标和验收标准。
- `v_k`：观测噪声，例如重复消息、缓存状态和不完整日志。
- `e_k`：真实输出与目标的偏差。
- `F` 和 `H` 不要求写出虚假公式，但必须用步骤、状态机或测试明确表达。

## 强制控制表

复杂分析至少填写一次：

| 字段 | 内容要求 | 错误做法 |
| --- | --- | --- |
| 目标状态 | 用户能够直接检查的结果 | “代码已修改”代替功能结果 |
| 状态变量 | 会随动作变化的内部状态 | 只记录最后一句用户消息 |
| 观测量 | 文件、测试、界面或外部结果 | 把函数未抛错当成最终成功 |
| 控制动作 | 能改变目标状态的实际动作 | 重复解释而不改变系统 |
| 扰动 | 权限、网络、焦点、版本差异 | 把扰动固化为用户偏好 |
| 时滞 | 构建、安装、刷新和人工反馈 | 未等待结果便宣布完成 |
| 稳定条件 | 重启、重复操作或扰动后仍正确 | 单次偶然通过 |
| 兜底路径 | 与主故障通道相对独立 | 在同一失败通道机械重试 |

## 方法选择

### 能观测性优先

当内部状态不可见时，先增加日志、文件检查、界面读取或目标端反馈。若现有观测不能区分多个故障原因，不应直接选择高影响控制动作。

### 能控性检查

确认当前工具、权限和通道真的能改变目标状态。只能写剪贴板却不能恢复目标窗口时，不能把“自动粘贴”设为当前可控目标。

### 稳定性与滞环

- 用重启、重新扫描、重复执行和不同窗口尺寸检查扰动后的恢复能力。
- 对长期偏好设置升级和降级门槛，避免一个新样本让规则来回振荡。
- 用户最新指令控制当前任务，长期模型使用更高的切换门槛。

### 时滞补偿

记录尚未完成的动作和预期反馈时间。构建、安装、浏览器重载或外部用户验证仍在等待时，不使用沉默更新规则。

### 随机与过滤

把网络失败、重复消息和偶发系统拦截看作随机扰动。只有当故障跨场景复现或有独立观测支持时，才升级为产品规则。

### 自适应与辨识

用小范围、可回退的动作识别未知行为。每次试探必须说明预期输出；结果用于更新模型，而不是仅记录“尝试过”。

### 容错与冗余

兜底通道必须尽量独立。例如浏览器扩展和系统键盘输入可以互为补充，但两个依赖同一错误焦点记录的重试不构成冗余。

### 大系统分层

把长期目标、项目模块、当前任务和单步动作分层。局部修复必须遵守数据、接口、测试和发布的上层约束。

## 控制策略模板

```text
当前误差：<目标与观测输出的差异>
最小控制动作：<下一步实际动作>
预期反馈：<能够区分成功与失败的信号>
等待时滞：<何时重新观测>
失败分支：<改变模型或切换通道>
稳定性检查：<重启/重复/扰动后的验证>
停止条件：<成功、需确认或阻塞>
```

## 禁止伪精确

- 不给无法量化的人类偏好虚构概率、小数置信度或数学参数。
- 不把工程稳定性直接等同于人的心理稳定性。
- 不因为使用公式而跳过对真实输入输出的验证。
- 不用控制论术语掩盖普通但必要的软件调试步骤。
